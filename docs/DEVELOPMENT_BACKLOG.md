# 개발 현황 및 잔여 작업

기준: 2026-10-31 로컬 소스 및 자동 테스트. 이 문서는 기존 보고서의 완료 표시를 재사용하지 않고 확인한 구현 범위를 기록한다. 배포 서버나 실제 교통 사업자 데이터의 정확성은 이번 작업에서 검증하지 않았다.

서버 실행 시 기본적으로 `var/travel-state.json`에 사용자 변경을 저장한다. 파일 하나는 서버 프로세스 하나만 사용해야 한다. 원자적 교체를 위한 임시 파일과 파일 동기화를 사용하지만, 운영 DB의 다중 프로세스 트랜잭션·마이그레이션·재해 복구를 대체하지 않는다. 시간과 요금은 시드 데이터 및 추정치이며 실제 시간표 기반 도착 보장은 구현되지 않았다.

그래프 라우터의 현재 범위는 접근 도보 1.5km, 정류장/역 간 도보 연결 300m 이내다. 도보는 직선거리 추정이며 실제 도로 연결성은 미검증이다. 지하철은 시드의 인접 역을 양방향으로, 버스는 정류장 순서대로 연결한다. 휠체어 경로는 탑승·하차·환승 지점의 엘리베이터와 휠체어 탑승 여부 및 버스 저상 여부를 검사한다. 엘리베이터 고장과 보행 경로 접근성은 확인할 수 없어 응답 및 화면에 별도로 안내한다.

## 검증

- 백엔드: `cd backend; go test ./...`, `go vet ./...` 통과.
- 프런트엔드: `cd frontend; flutter analyze --no-pub`, `flutter test --no-pub` 통과. 위젯 테스트는 기존 4개, 일정 API 성공·실패 2개, 일정 편집·삭제·재정렬·여행 삭제 상호작용 1개로 총 7개.
- 새 회귀 범위: 다중 지하철 환승, 지하철+버스 및 버스 환승, 대체 접근역, 선호 기준, 순환선, 버스 역방향 제외, 휠체어 불가 환승역 제외, 시간 합계, 날짜별 예보, 일정 CRUD 및 HTTP 400/404, 파일 저장·재시작·백업 복원·삭제·저장 실패·손상 파일, 요청 크기 제한.
- 미검증: 실제 사업자 데이터, 실제 위치 기반 접근성, 브라우저/기기 시각 검수, 공개 배포 서버, 운영 DB 및 다중 서버 복구.

## 로컬 실행 및 데이터 보관

백엔드 디렉터리에서 실행한다.

```powershell
go run ./cmd/server -port 8080 -data-file ./var/travel-state.json
```

데이터 파일 경로는 실행 디렉터리를 기준으로 해석한다. 서버를 중지한 뒤 파일을 별도 위치에 복사하면 백업할 수 있다. 복원은 복사본을 새로운 경로에 두고 `-data-file`로 지정한다. 파일이 손상되면 서버가 시작을 거부하므로, 기존 파일을 보존하고 정상 백업을 사용해야 한다. 테스트와 일부 임베딩 코드는 기존 메모리 생성자를 계속 사용한다.

외부 자료가 필요한 항목은 연결 코드와 테스트를 먼저 작성할 수 있지만, 실제 서비스 동작의 완료 판정에는 해당 자료와 운영 검증이 필요하다.
